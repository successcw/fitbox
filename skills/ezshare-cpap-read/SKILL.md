# ezShare 呼吸机数据读取

把卡留在实际使用的呼吸机中，完成无线读取、文件验证及采集端网络恢复。读取协议与验证细节见 [references/protocol.md](references/protocol.md)，首次执行、移植或排错时读取。

这是依赖项目实现的 skill 草稿，尚非独立可执行软件包。以下路径均相对于包含本 skill 的项目根目录：

- `fitbox/cpap_pull.py`：网络切换、独立恢复、每日成功标记和命令行入口。
- `fitbox/cpap_legacy.py`：旧入口与直接路径回退、STR 解析、候选探测及会话覆盖验证。
- `fitbox/watch.py`：接收侧同步；日报生成和发送是另外的流程。
- `fitbox/test_cpap_pull.py`、`fitbox/test_cpap_legacy.py`、`fitbox/test_legacy_schedule.py`：实现的回归测试。

如果这些文件不可用，先说明缺少实现，不能把本文当作已安装的命令。部署前按目标环境配置网络连接、目标目录、凭据和接收端；不要沿用作者的环境值。

## 执行要点

1. 确认用户授权的采集设备、目标日期及本地存储位置。通过现有远程连接进入树莓派，核对固件与日志。不要把一次下载 404 当作卡上没有文件。
2. 切换树莓派网络前，记录原连接并启用独立于采集服务生命周期的恢复任务。单无线网卡离开家庭网络时远程 SSH 暂时断开是预期行为；设置总离网期限，任务结束后核实实际连接已恢复。不要连带切换 Mac 网络。
3. 在卡保持插在呼吸机的状态下验证读取。已验证旧固件采用 `--legacy-scan`；先刷新并严格验证 STR，再按其中的治疗日和会话时间探测数据。文件逐个落盘并记录 SHA256。参照实现的 `--help` 配置参数，不用目录扫描模式替代旧协议扫描。
4. 分别报告文件读取、STR 会话覆盖、网络恢复。只有覆盖验证通过且扫描完成，才能写入该范围的成功记录；不能称为卡的完整镜像。
5. 每天早、晚任务都启用 `--if-missing`。只有“今天已核验昨天治疗日”的成功记录能跳过晚上任务；旧数据、只有 STR、超时或未结束会话不算成功。
6. 用户问日报是否送达时，继续检查接收端文件哈希、日报使用的治疗日期及发送结果。采集日志不是发送凭证；把“树莓派已下载”“Mac 已收到”“日报已生成”“消息已发送”四个状态逐项核实。

## 排错边界

已验证的是一块 `LZ1001EDPG:4.4.0 / LZ1001EDRS:4.4.0` 旧照片固件卡与本项目 ResMed 数据格式的组合。不能推断其他 ezShare 固件、克隆卡或其他呼吸机型号具有相同行为。新组合先做有界只读探测，再启用定时采集。

保留实际 Wi-Fi 环境进行比较，不要求用户拔卡到读卡器来替代热点验证。普通排错不写卡、不格式化、不调用固件重置或上传接口。一次扫描达到总期限即保存进度并恢复网络，不无限重试。发布材料只包含脱敏的协议和代码，不包含原始 EDF、Journal、序列号、凭据或私人网络配置。
