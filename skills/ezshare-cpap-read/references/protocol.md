# 协议与验证记录

## 证据范围

2026-10-17 的实测中，卡留在呼吸机内，树莓派连接卡的热点后，直接路径成功读取 STR 和目标夜的五类 EDF 及配套文件；接收端 SHA256 一致，STR 会话覆盖核验通过。旧下载接口在同一环境仍返回 404。卡插读卡器时旧接口曾成功，因此必须在实际宿主设备中复核，不能仅凭固件版本选择唯一入口。

已验证版本为 `LZ1001EDPG:4.4.0:2014-07-28:62` 和 `LZ1001EDRS:4.4.0:2014-07-28:62`。以下是本组合的可复现方法，不是厂商协议保证。

## 入口与假成功

以 `CARD_BASE_URL` 表示当前热点网关的 HTTP 地址；下列为相对 URL，不含私人网络配置。

| 用途 | 请求 |
| --- | --- |
| 确认卡固件 | `/client?command=version` |
| 旧接口读取汇总 | `/download?fname=STR.EDF&fdir=..` |
| 旧接口读取明细 | `/download?fname=<文件名>&fdir=..%5CDATALOG%5C<治疗日>` |
| 直接读取汇总 | `/STR.EDF` |
| 直接读取明细 | `/DATALOG/<治疗日>/<文件名>` |

现实现先请求旧接口，404 后尝试直接路径。路径段需正确 URL 编码，禁止接受绝对本地路径或 `..` 目录穿越。禁用 HTTP 代理，确认请求实际到卡上。短文件名限制在社区有报告，但本组合原始长文件名可用，不能预设必须转换 8.3 名称。

直接路径请求不存在文件时，实测返回 **HTTP 200、219 字节 HTML**，其中有 `REDIRECTFORM`，跳向 `http://ezshare.card/publicdir/welcome.htm`。不能仅凭状态码或文件扩展名判成功。实现对已确认的完整欢迎页模板做精确匹配，将其记为缺失；其他内容交由 EDF 验证器检查，不能把所有小响应都当作不存在。

旧 `/dir?dir=A:` 返回欢迎页，照片列表接口不能可靠列举 EDF。它们的空结果不证明目录或文件不存在。旧接口的通用 404 文案也不证明目录改变、DCIM 被删、卡被格式化或供电异常。旧读卡器实验中空 DCIM 曾影响旧入口，但不能把创建 DCIM 当作所有场景的必要步骤。

## 从 STR 找到文件

`STR.edf` 是每日汇总，包含使用时长、MaskOn/MaskOff、呼吸事件指数等；不包含逐秒波形或全部事件明细。每次扫描刷新 STR，不能只按文件大小判断变化。

此格式每条 STR 记录跨度 86400 秒。依据 EDF 起始时间和记录序号确定治疗日；本组合日界是中午。MaskOn/MaskOff 是相对该日界的**分钟**偏移。目录使用治疗日，文件名使用真实钟表日期：凌晨的文件通常位于前一天治疗日目录，不能要求两者日期相同。

STR 只有分钟精度，文件名精确到秒。实现以每次 MaskOn 为锚点，逐秒探测前 10 秒至后 120 秒，类型为 `BRP`、`PLD`、`SAD`、`CSL`、`EVE`；命中 EDF 后获取同名 `.crc`。各类型开始秒数可能不同，不能用一个 PLD 文件名推定所有其他文件名。入口的正式调度采用开始时间候选；底层工具另支持结束时间候选。

首次默认从最近两天开始，后续沿已下载日期接续，也可显式指定 `--since YYYYMMDD`。未落入候选窗口的独立启动文件可能漏掉，因此这不是通用目录枚举。

`Journal.dat` 曾提供有用的 FAT 长文件名片段，可用于确认候选文件名，但内容并不保证包含所有文件，历史实测缺少部分 CSL/EVE。不要把它当成公开稳定格式、完整目录或生产同步的唯一清单。

## 下载、缓存和完整性

- 每个文件先写 `.part`，验证后原子替换；失败保留原有有效文件。
- EDF 必须有有效头部、信号数和记录数，实际长度须精确匹配头部及各信号采样数。尚未封口、截断或 HTML 响应拒绝落盘为有效 EDF。
- `.crc` 在本组合实测为 8 字节，现实现检查长度、存在性及同步哈希；**没有反向实现其校验算法，不能声称已经用厂家 CRC 校验 EDF 内容**。
- 为每份落盘文件记录字节数和 SHA256；接收端对照，不能仅凭文件名或大小认定接收成功。
- 短期探测缓存由 STR 哈希、日期、起始日期、候选范围及协议版本共同确定，最长复用一小时。只有当日所有会话已结束超过五分钟，才复用缺失候选记录；修复入口后让旧 404 缓存失效。
- 请求、整轮扫描及重连均有期限。现实现瞬时错误最多三次请求，整轮最多两次重连；不要将 404 当作网络故障反复重连。

## 成功究竟意味着什么

只有扫描完成、没有错误且目标治疗日通过验证，才记 `scope: str-session-coverage`，同时保持 `mirror_complete: false`。检查内容包括：

- MaskEvents 与可见的有效会话数相符，槽位未用满，每个会话有有效结束时间。
- BRP、PLD、SAD 时间区间合并后覆盖 STR 所列会话；两端容许一分钟精度差，内部不容许缺口。
- CSL/EVE 有首会话附近的 `Recording starts`，所接受 EDF 有有效长度的配套 CRC 文件。
- EVE 呼吸事件没有重复、没有越过治疗日边界，已知六类计数与 STR 对应；未知事件或计数歧义会拒绝通过。

本设备指数实测向下截断到 0.1。若指数为 `I`、使用时长为 `D` 分钟，计数必须是区间 `[I × D / 60, (I + 0.1) × D / 60)` 中唯一整数。与 EVE 整夜计数核对。此取整规则只经当前设备验证，移植前须核对，不能套用于所有 ResMed 型号。

上述验证不保证额外空启动文件、全部 Arousal 或卡的所有文件都已枚举。单独 STR 可以生成汇总，但不足以写入整夜会话覆盖成功标记。当天独立成功记录还需标明昨夜治疗日，才能让晚间 `--if-missing` 在切网前退出。

## 网络恢复与消息链路

单网卡树莓派连接卡时会离开原网络。采集前用独立 `systemd-run` 定时恢复任务提供兜底；不要只从采集进程启动子进程，因为服务退出时同一 cgroup 可能一起被终止。必须先成功建立恢复任务，再暂停网络监控并切网。

采集结束执行恢复，核对实际活动连接，再恢复网络监控；只有恢复成功且监控已启动，才取消本轮专属的兜底任务。连接超时后核对真实状态，重试前取消未完成的连接请求，防止后续异步切网。总离网期限要覆盖扫描和有限恢复时间。远程会话断开期间依靠本地服务完成工作，随后重连读取日志。

数据处理分为四段，各留独立证据：

| 阶段 | 应核实的证据 |
| --- | --- |
| 树莓派采集 | 目标治疗日、落盘清单、哈希、覆盖结果、恢复网络结果 |
| 接收端获取 | 接收日志与相同文件哈希，STR 内容已更新 |
| 生成日报 | 报告实际包含目标治疗日数据，迟到数据是否触发重新生成 |
| 发送消息 | 发送接口的成功结果或消息标识；不能只看“计划发送”日志 |

本项目接收过程由 Mac watcher 消费采集日志并获取文件，不应笼统描述为树莓派主动推送。早间日报可能在呼吸机数据到达前已经发送，后到文件是否补发取决于报告调度实现；排查时单独核实，不把采集成功等同于用户收到日报。

当前日报修复方案：只有通知接口返回成功才记录发送状态，失败可重试；按日报日期另存是否包含呼吸机数据，先发缺失版后数据到齐时允许一次更新，线程锁防止并发回调重复发送。旧版仅日期标记无法判断发送内容，应保守处理；手动补发须获得明确外发授权。接口成功表示服务接受请求，不等于用户已读。
